# 提纲
- 目标：修复 Cardputer 通过 LAN / 远程模式获取的数据与桌面端不一致问题
- 根因：桌面端默认显示「当天」数据，LAN 服务和远程服务返回全部历史数据
- 涉及文件：
  - src-tauri/src/services/lan_broadcast.rs（LAN Axum 服务）
  - /Users/simon/usage-monitor-server/server.js（远程 Node.js 服务）
  - cardputer-monitor/src/main.cpp、src/config.h（固件 v1.5）
- 关键决策：默认时间范围设为「当天 00:00～现在」
- 未完成：部署 server.js 到 VPS(111.231.44.136)需用户提供 SSH/部署方式

## 正文

### 根因分析
Windows cc-switch 桌面端 UsageDashboard 默认 preset="today"（当天数据）。
Cardputer 通过 LAN（Axum 3345）或远程（Node.js 3344）获取数据时，
未传任何时间参数，服务端返回全部历史累计数据，与桌面端相差数十倍。

### LAN 服务端修复（cc-switch）
src-tauri/src/services/lan_broadcast.rs
- 新增 DateRangeQuery 结构体，start_date/end_date 可选参数
- 不传参时默认取当天 00:00 UTC～现在
- handle_summary / handle_logs / handle_trends 全部应用

### 远程服务端修复（usage-monitor-server）
/Users/simon/usage-monitor-server/server.js
- /api/v1/summary：不传 since/until 时默认取当天
- /api/v1/logs：同上

### 固件 v1.5 更新
- IP 输入修复：. 号不再触发字段切换，作为合法 IP 字符
- 退格键：逐字符删除当前字段，不退出
- Tab 键返回上级菜单
- prev* 状态复位修复：按键抬起时复位所有 prev 标记
- 版本号 v1.4 → v1.5

### 构建说明
- cc-switch Windows 版：推 GitHub → Actions 自动编译
- cc-switch macOS 版：本地 cargo tauri build
- 固件：本地 platformio run（/Users/simon/cardputer-monitor）
